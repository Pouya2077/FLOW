# Django in FLOW

One Django project serves both the web page and the JSON API. The API uses **Django Ninja**, not
Django REST Framework and not FastAPI. There is **no database**: the web app only serves the GeoJSON
that the offline pipeline writes. CLAUDE.md has the product rules (three road states, observation
time, radar limits); follow them in everything below.

## Layout

```
config/                 Django project
  settings.py           no DATABASES; FLOOD_DATA_DIR, GEOCODER_URL, GEOCODER_USER_AGENT
  urls.py               "" -> flood.views.index, "api/" -> flood.api.api.urls
flood/                  the only app
  api.py                NinjaAPI instance and every /api route
  data.py               reads data/locations/**; cached per process with functools.cache
  views.py              page views (just index)
  templates/flood/      page templates (index.html is a placeholder for the map UI)
  tests.py              SimpleTestCase smoke tests with a temporary data folder
data/locations/<slug>/  output of the offline pipeline, one folder per demo location
pyproject.toml          dependencies + [tool.ruff] config (Python's package.json, minus scripts)
uv.lock                 locked versions; commit it
```

## Commands

Everything runs through **uv**. Never call `pip`, and never run `python` outside `uv run`.

| Task | Command |
|---|---|
| Install / sync deps | `uv sync` |
| Dev server | `uv run python manage.py runserver` → http://127.0.0.1:8000 |
| API docs | http://127.0.0.1:8000/api/docs (generated by Ninja) |
| Tests | `uv run python manage.py test` |
| Django checks | `uv run python manage.py check` |
| Lint | `uv run ruff check .` (add `--fix` to auto-fix) |
| Format | `uv run ruff format .` |
| Pre-commit (all files) | `uv run pre-commit run --all-files` |
| Add a dependency | `uv add <pkg>` (dev-only: `uv add --dev <pkg>`) |

Before you call a change done, run `ruff check --fix`, `ruff format`, `manage.py check` and
`manage.py test`, and report the results honestly.

## Data format (data/locations/<slug>/)

The folder name is the location's `slug`. Each folder contains three files:

- `meta.json` — `name`, `bbox` `[minx, miny, maxx, maxy]` in lon/lat (EPSG:4326), `observed_utc`
  (ISO 8601), `sensor`, and optionally `footprint` (GeoJSON Polygon of radar coverage) and
  `synthetic: true` for test masks.
- `segments.geojson` — FeatureCollection of LineString/MultiLineString road segments. Properties:
  `name`, `highway`, `osm_way_ids`, `status` (`flooded` | `clear` | `no_data`), `flooded_fraction`,
  `confidence`, `observed_utc`.
- `streets.json` — list of `{name, total_m, flooded_m, pct, observed_utc, bbox}`.

All coordinates the API serves are lon/lat (EPSG:4326). Metre lengths are computed earlier, in the
pipeline (in a projected CRS), never in the web app. `data.py` loads files once per process, so
**restart runserver after regenerating data**. In tests, call `.cache_clear()` on the loaders.

## Adding an API route

Put it in `flood/api.py` on the existing `api` object. Do not create a second `NinjaAPI`.

```python
@api.get("/something")
def something(request, bbox: str):
    """One-line docstring — it becomes the description in /api/docs."""
    view = _parse_bbox(bbox)  # reuse the helper; it raises 400 on bad input
    ...
    return {...}  # plain dicts/lists are fine; Ninja serialises them
```

Rules:
- Errors: `raise HttpError(status, "message") from None`. Use 400 for bad input, 404 for an
  unknown location and 502 when an upstream service (the geocoder) fails.
- `bbox` query params are always the string `minx,miny,maxx,maxy`; parse them with `_parse_bbox`.
- Keep file I/O in `data.py` and request handling in `api.py`. Do no raster maths per request; heavy
  work belongs in the offline pipeline.
- External HTTP: send `settings.GEOCODER_USER_AGENT`, set a timeout and cache results with
  `django.core.cache`. Only free services (Photon, Nominatim); no Google APIs or keys.
- If a response shape firms up, a Ninja `Schema` (`from ninja import Schema`) is welcome for
  docs/validation. Keep fields matching the CLAUDE.md data contract.

## Pages and frontend

- Views go in `flood/views.py`, templates in `flood/templates/flood/`, and static files in
  `flood/static/flood/` (load them with `{% load static %}`).
- The map is MapLibre GL JS, loaded from a CDN, with the OpenFreeMap basemap. The page's JS calls
  `/api/...` on the same origin, so no CORS setup is needed.

## Settings

- No database. Don't add `django.contrib.admin`, `auth`, `sessions` or models/migrations unless the
  team agrees to add a DB. If you do, a migration step joins the setup.
- Configure through env vars: `DJANGO_SECRET_KEY`, `DJANGO_DEBUG` (`1`/`0`) and
  `DJANGO_ALLOWED_HOSTS` (comma-separated). Never commit real secrets.
- New project-specific settings go at the bottom of `config/settings.py` in UPPER_CASE, with a
  one-line comment explaining why.

## Tests

- Use `django.test.SimpleTestCase` (no DB). Copy the `ApiSmokeTest.setUp` pattern: write fixture
  files to a `TemporaryDirectory`, then `override_settings(FLOOD_DATA_DIR=...)` and clear the
  `data` caches.
- Never make tests hit the real geocoder. Mock `urllib.request.urlopen` instead.
- Add at least one test for every new route, including its error path.

## Style

- Ruff settings are in `pyproject.toml`: line length 100, py312, rules `E F I UP B DJ`. Let
  `ruff format` decide layout, and don't hand-format against it.
- Use modern typing (`list[dict]`, `X | None`) and `pathlib`. Docstrings go on route handlers and
  modules; elsewhere add comments only where the *why* isn't obvious.
- Keep it small: this is a 24-hour hackathon build. Prefer the simplest thing that works and don't
  add frameworks (DRF, Celery, React build tooling) without the team agreeing.
